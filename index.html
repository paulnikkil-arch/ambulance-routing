Getting an ambulance through Bengaluru traffic: a routing prototype

A city is a grid of road cells. Some are blocked (flyover works, waterlogging), some jammed. The prototype finds the fastest route from the ambulance to the hospital and compares four algorithms on the same map.

1. Problem, inputs, outputs, algorithm

Problem. Given a road network with different travel times, find the minimum-time path from an ambulance (source) to a hospital (destination). Minutes matter, so the shortest path in cells is not good enough: a short road through a jam can be slower than a longer clear one.

Input. An N×N grid. Each cell has a cost to enter: 1 (clear), 5 (traffic), or blocked. A start cell and a hospital cell.

Output. The route, its total travel cost, and how much work the algorithm did (cells expanded, milliseconds).

Chosen algorithm. A* with a Manhattan-distance heuristic, using Dijkstra's algorithm as the correctness baseline. Breadth-first search (ignores traffic) and Bellman-Ford (handles any edge weights) are the alternatives compared.

    5. Why this algorithm

    • A* is Dijkstra guided by a goal-directed estimate. Manhattan distance never overestimates on a 4-direction grid whose cheapest cell costs 1, so A* stays optimal while exploring far fewer cells. That is why it suits a single source and single hospital.
    • Dijkstra is optimal for non-negative weights but explores in every direction. It is the right choice when one source needs routes to many hospitals.
    • BFS is fastest per cell but treats every road as equal, so it walks into traffic. The benchmark shows the extra travel time it causes.
    • Bellman-Ford is only needed for negative weights, which travel time never has. It is far slower here.

    6. Complexity

    AlgorithmTimeSpaceOptimal on weighted roads?
    Dijkstra (binary heap)O((V+E) log V)O(V)Yes
    A* (admissible heuristic)O((V+E) log V) worst case, usually far lessO(V)Yes
    BFSO(V+E)O(V)No (fewest cells only)
    Bellman-FordO(V·E)O(V)Yes

    On a grid, V = N² and E ≈ 4N², so doubling N quadruples V. The benchmark above shows this growth, and the much slower rise for A*.

    7. Limits and next steps

    Costs are static; real traffic changes by the minute. Next steps: load real road data (OpenStreetMap), feed live congestion into the weights, and re-run A* as conditions change (D* Lite does this incrementally). Ambulances could also be sent to the nearest of several hospitals by running Dijkstra once from the ambulance.

    Algorithms are implemented from scratch in this page's script (binary heap, no libraries).
